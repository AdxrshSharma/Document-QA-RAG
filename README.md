# Local Document Q&A — RAG

A locally running PDF question-answering application built with **Retrieval-Augmented Generation (RAG)**, ChromaDB, Sentence Transformers, and extractive question answering, with optional Ollama integration for local LLM-generated answers.

Ask questions about your documents and get answers based on relevant passages retrieved from your PDFs.

## Features

* **PDF ingestion:** Extracts text from PDF documents and splits it into manageable chunks.
* **Semantic search:** Uses Sentence Transformers to represent text as embeddings and retrieve relevant passages.
* **Vector database:** Stores and searches document chunks locally using ChromaDB.
* **Extractive QA:** Uses DistilBERT to identify answer spans from retrieved text.
* **Optional local LLM:** Supports an Ollama-based answer engine, subject to local installation and configuration.
* **Source references:** Displays the source document and page associated with an answer.
* **Evaluation tools:** Includes an evaluation script and a test dataset for experimenting with answer quality.
* **Local processing:** Designed to run on your own computer without requiring a paid LLM API.

## How It Works

The application follows a Retrieval-Augmented Generation (RAG) workflow.

1. **Document ingestion:** PDFs are loaded and their text is extracted.
2. **Chunking:** Extracted text is divided into smaller, overlapping sections.
3. **Embedding generation:** Sentence Transformers converts the chunks into numerical vectors.
4. **Vector storage:** ChromaDB stores the vectors and associated document metadata.
5. **Retrieval:** A user's question is embedded and used to find relevant document chunks.
6. **Answer generation:** The selected answer engine processes the retrieved passages.
7. **Source attribution:** The application displays the answer along with source information when available.

### Answer Engines

**Extractive QA**

Uses DistilBERT to select an answer span from the retrieved text. It is useful for direct questions but may return incomplete or incorrect answers when retrieval or extraction is inaccurate.

**Local LLM via Ollama**

An optional answer engine that uses a locally running language model to generate more natural-language answers from retrieved context. Ollama and a compatible model must be installed and running.

## Prerequisites

* Python installed on your computer
* Git (optional, for cloning the repository)
* Internet access for installing Python packages and downloading models for the first time
* Ollama only if you want to use the local LLM answer engine

## Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/AdxrshSharma/Document-QA-RAG.git
cd Document-QA-RAG
```

Alternatively, download the repository as a ZIP file from GitHub.

### 2. Create a virtual environment

On Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Generate a sample PDF

```powershell
python make_sample_pdf.py
```

Use the sample PDF generated by the script for initial testing.

### 5. Index the documents

```powershell
python ingest.py
```

Place any additional PDFs you want to query in the project's `data/` folder before indexing them.

### 6. Start the application

```powershell
streamlit run app.py
```

Open the local URL shown in the terminal to access the application.

## Optional: Ollama Setup

To use the local LLM answer engine:

1. Install Ollama from [ollama.com/download](https://ollama.com/download).
2. Download a model supported by your application's configuration.
3. Ensure Ollama is running.
4. Select the local LLM answer engine in the application.

For example, if your application is configured to use Llama 3.2 3B, you can download it with:

```powershell
ollama pull llama3.2:3b
```

You can verify the model independently with:

```powershell
ollama run llama3.2:3b
```

The model name used by the application must match an installed model. Ollama also requires sufficient local memory and processing resources.

## Evaluation

The repository includes `evaluate.py` and `eval_set.json` for testing answer quality.

To inspect the evaluation script and its available options, run:

```powershell
python evaluate.py --help
```

Evaluation results can help identify issues with retrieval relevance and answer extraction. A high extraction confidence score should not be treated as proof that an answer is correct.

## Privacy and Limitations

* Documents, embeddings, and the vector database are intended to remain local.
* Model downloads may require internet access initially.
* Extractive QA can select irrelevant text or fail to identify an answer.
* Local LLM answers may be inaccurate or include unsupported details.
* Keep private documents, API keys, credentials, and environment files out of the public repository.
* Do not upload personal resumes or confidential PDFs when demonstrating the project.
